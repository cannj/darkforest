# 本地双人试玩

需要 Node.js 24 LTS。首次执行 `npm ci`。

分别打开两个终端，在项目目录运行 `npm run server` 和 `npm run dev`。房间服务默认监听 `127.0.0.1:8788`，Vite 将 `/room` WebSocket 代理到该服务。

在两个独立浏览器窗口中访问终端显示的页面地址，在地址后添加相同的 `?room=demo-1`。新标签页分配一个座位，房间默认两个座位。每个标签页按房间保存自己的不可猜测恢复凭证；断网会自动重连，刷新仍回原座位。不要复制凭证到其他浏览器，持有该凭证的新连接会替代旧连接。服务进程重启会结束活动房间，重新试玩请更换房间名。

依次选择方向添加移动，点击「等待」添加空拍，可用「清空重排」重新选择。然后点击「提交计划」查看自己的草稿，再点击「锁定计划」。双方锁定后服务端统一结算，各自棋子更新位置并进入下一回合。也可提交空计划以等待。每轮固定四拍，最多两次移动（含斜向），等待不占移动额度。后续目标按该拍的实际位置检查，受阻不会取消后续行动。同拍争抢目标格、进入拍初被占据的格子（含交换）暂统一受阻。页面列出自己的四拍结果，「播放上轮」逐拍更新棋子。公开地图是石室中央的 5 × 5 格棋盘，坐标从 0 开始。亮格为当前视野，暗格为迷雾；橙色棋子为自己，绿色棋子为当前可见目标，空心标记为旧目击。页面记录旧目击的回合与拍数。「播放上轮」只使用该座位各拍获准观察的片段，隐藏路径和对手计划留在服务端。

`npm test` 验证房间公开流程，`npm run build` 检查严格类型并构建浏览器和服务端。`node dist-server/server/index.js` 可启动编译后的房间服务。浏览器生产文件位于 `dist`，正式提供页面时需将 `/room` WebSocket 转发到房间服务。

首次运行端到端测试前执行 `npx playwright install chromium`，之后运行 `npm run test:e2e`。测试自行启动 Vite 和房间服务，占用 5174、8788 端口。已有 Chromium 时可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指向其可执行文件。截图存入忽略的 `artifacts` 目录。

首版格边实现约定如下。墙和关闭的门同时阻挡通行与视线，开启的门可通过且透明。窗透明，正交跨窗按翻窗处理，占一次移动额度；斜向不跨窗。斜角视线保守要求两条正交绕角路径的四条格边全部透明，斜向通行单独检查四条格边可普通通过。这是当前切片的默认裁定，后续玩法可以在独立规则入口调整。

地图数据完整声明每格材质与唯一正交格边，校验越界、重复和相邻关系。动态门状态单独保存在服务端。只向玩家下发观察到的门状态与带回合、拍数的地形记忆。`Room(id, setup)` 可配置 `board`、`terrain.doors`（未声明的门默认关闭）、`spawns` 和 `visionRange`（默认一圈），测试直接通过这个公开流程切换布局。客户端不提供开关门交互。

房间满员后开始服务端计时。默认计划阶段 30 秒，双方提前锁定或到达截止时统一结算，结算阶段显示 1 秒后进入下一轮。环境变量 `ROUND_DURATION_MS`、`SETTLEMENT_DURATION_MS` 可调整这两个时长。未锁定草稿超时补等待，锁定计划即使离线也会执行。倒计时使用服务端阶段截止时间，并按消息中的服务端时间校正浏览器时钟。对方提交草稿或锁定时不会向本座位广播。

`Room(id, setup, runtime)` 的 `runtime` 可注入 `now`、`roundDurationMs`、`settlementDurationMs`。`tick()` 与命令共用结算入口；命令先处理已到截止的阶段，再校验回合和请求编号。默认房间结算阶段时长为零，便于同步规则测试；实际服务器显式配置结算阶段。长期离线或主机时钟大幅跳变时一次最多处理十个阶段，再以当前时刻安排下一截止，避免阻塞服务。

## 记录并复盘实际对局

服务端默认把满员房间写入 `.local/matches/<房间名>-<唯一编号>.jsonl`，该目录由 Git 忽略。房间名经过协议校验。同名房间在服务重启后生成新文件。每个文件首行记录格式、地图拓扑与版本、规则版本、配置版本及初始座位位置；后续每行对应一个已结算回合，立即写入磁盘。`inputs` 的 `locked` 保留玩家锁定的原始计划，包含显式等待；`timeout` 表示服务端丢弃未锁定草稿后补入整轮等待。当前规则完全确定，不使用随机数，无需种子。

完成两轮试玩后，在服务端本机运行以下 PowerShell 命令，读取最新记录并验证。

```powershell
$match = Get-ChildItem .local/matches/*.jsonl | Sort-Object LastWriteTime -Descending | Select-Object -First 1
npm run replay -- $match.FullName
```

成功时输出房间名和已核对的回合数，例如 `{"roomId":"demo-1","rounds":2}`。未知格式、规则或配置版本、非法计划、缺失座位、回合顺序错误和结算差异均以非零退出码拒绝。复盘用记录中的完整地图与配置，通过同一个 `Room` 的加入、提交、锁定及截止入口重跑；逐轮比较权威状态与每拍结果的 SHA-256 摘要，以及每个座位逐拍观察、地图记忆和对峙的摘要。摘要按对象键排序计算。复盘以可控时钟推进截止，不比较网络时间和阶段停留时长。规则或固定配置发生行为变更时须更新 `rulesVersion` 或 `configVersion`；旧记录应使用对应 Git 版本的实现验证。

要覆盖对峙和超时，在第一轮让 p1 锁定空计划，p2 提交西北移动并锁定。下一轮 p1 锁定空计划，p2 提交向南移动但保持未锁定，等待截止。第二轮 p2 仍停在 `(2, 2)`。自动验证同一流程可运行 `npm run test:e2e -- e2e/replay.spec.ts`，它打开两个隔离 Chromium 会话并通过开发 CLI 复盘，同时对比服务实际下发的观察摘要。测试记录默认写到 `artifacts/matches`；设置 `MATCH_LOG_DIR` 可指定服务和测试共用的目录。

手动启动服务时也可设置 `$env:MATCH_LOG_DIR = 'C:/local/darkforest-matches'`。记录包含服务端完整信息，只供本机开发入口读取，浏览器不会收到记录下载地址。
