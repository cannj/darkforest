# 黑暗森林对局架构

本文记录首个联机里程碑的底座。一张公开的逻辑地图、两个浏览器玩家和一局可复现的对局，足以验证棋盘、回合、迷雾、对峙和重连。三人场景用于验证局部对峙。对局用语见 [项目术语](../GLOSSARY.md)。

经典地图的探索规则见 [ADR 0002 按玩家视野探索地图](adr/0002-explore-map-through-player-vision.md)。

## 棋盘和回合

逻辑地图描述格子、地面和格边。格子用行列坐标标识。门窗附在相邻格子之间的边上。玩家位置是占位的唯一来源，每格最多有一名玩家。移动和视线分别查询棋盘，所以窗户可以在通行和透视上使用不同规则。

首版采用单层地图，支持斜向移动。视野覆盖身边一圈，包含斜角，并受门墙遮挡。圈外进入迷雾。每轮最多安排两次移动，翻窗占一次移动额度。移动额度独立于行动点和结算拍数。

全房间共用一个回合。玩家各自提交并锁定计划，房间在到达结算条件时把计划一并交给引擎。引擎从同一拍的状态裁决该拍行动，再一起提交结果。普通行动失败时，后续行动仍在原定拍数按当时的状态检查。

两个玩家进入彼此视野时触发对峙，参与者当轮停在各自所在格，其他玩家继续结算。对峙记录随对局状态带入下一轮。**对峙关系**与**本轮停止**分别记录，所以参与者下一轮可以在同一个计划阶段继续行动。

首版斜角视线保守检查两条正交路径的全部格边，移动单独检查通行。窗透明，正交翻窗占一次移动额度，斜向不跨窗。当前实现约定见 [本地试玩](local-play.md)。

同格争抢、花 2 点的动作在哪一拍生效，以及对峙期间可选的动作，留待具体玩法设计。规则引擎提供这些裁决的统一入口。

## 模块边界

| 模块 | 负责的数据和行为 |
| --- | --- |
| 逻辑棋盘 | 读取地图、校验地图布局，提供格子和格边查询。地图定义随对局版本固定，开关门等地形变化由对局状态记录。 |
| 对局规则 | 管理权威对局状态，包含回合、玩家位置、地形变化和对峙。计算行动合法性、每拍结果和详细的内部事实。规则输入是当前状态、锁定计划和对应的地图与规则版本。 |
| 玩家视图 | 按玩家生成当前可见状态、地图记忆、已获知的提示和可播放的结算片段。每拍计算该玩家可获知的事实，记录短暂目击的回合和拍数。 |
| 房间服务 | 绑定连接与玩家身份，接收计划、锁定计划、管理截止时间和超时补等待。每个房间通过同一个入口提交状态变更，并向各玩家发送各自的视图。 |
| Three.js 客户端 | 将格子映射到场景坐标，显示迷雾、玩家位置和结算动画。收集输入并提交计划。现有正交镜头、像素化渲染和石室模型由表现层继续使用。[渲染入口](../src/main.js) · [石室场景](../src/room.js) · [像素风格规范](pixel-style.md) |

房间向规则引擎提交一整轮已锁定的计划。规则引擎按拍推进，玩家视图在结算过程中采集观察事实。房间按自己的时钟推进阶段，客户端用服务器给出的截止时间显示倒计时。

## 联机与复盘

玩家命令绑定玩家身份、回合编号和请求编号。房间按这三个字段识别重发，旧轮次的请求无法修改新一轮计划。提交计划时只返回该玩家可以获得的信息。完整棋盘状态、其他玩家的计划和内部结算记录留在服务端。

浏览器断线时，对局照常推进。已锁定的计划照常执行，超时未锁定的玩家按等待处理。玩家回到原座位后，从同一个玩家视图入口恢复当前视野、地图记忆、授权提示、自己的计划锁定状态和剩余时间。玩家视图只携带已经获准看见的动画片段。

房间以权威状态快照作为当前状态。开发复盘记录初始状态、地图和规则版本、按轮锁定的计划及超时补入的等待。规则使用随机时记录随机种子。复盘时加载对应版本的地图、配置及规则实现，重跑同一个引擎，核对结果和逐拍观察。房间运行在实际时钟上，引擎只接收房间已作出的裁决输入。

地图布局、距离、移动上限和物品内容用配置表示。新的行动或地形行为通过规则代码实现。将来新增一种行为时，房间仍提交计划和分发视图，客户端按视图中的可见结果更新。

## 实现与验收顺序

1. **无画面结算。** 用小地图验证斜向移动、移动上限、每格最多一人、受阻后后续动作仍能执行，以及对峙的轮次边界。用三人对局验证未参与对峙的玩家能继续行动。
2. **逐拍生成玩家视图。** 给同一局生成两份视图，验证短暂目击只送给当时能看到的玩家。检查结算片段与实际下发的数据，再把视图接到暮林石室。
3. **双浏览器联机。** 验证重复提交、截止、超时、断线期间继续结算和重连恢复。用记录重跑同一局，核对权威结算结果和逐拍观察。

运行时、联机传输、校验和测试工具见 [首版技术栈决策](adr/0001-initial-technology-stack.md)。
